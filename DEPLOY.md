# Putting AI Interview Copilot on a real web address

Right now the app runs only on this laptop, at `http://localhost:3100`, and
only while `npm run dev` is running. This file is what turns that into a URL
you can open from your phone, or from a faster computer during an actual
interview.

## What it costs, and where you pay

**$7.25 a month**, as two separate charges on the same Render bill:

| Item | Cost |
| --- | --- |
| Starter web service (512 MB RAM, 0.5 CPU) | $7.00 / month |
| Persistent disk, 1 GB at $0.25/GB | $0.25 / month |

**You pay at <https://render.com>.** Signing up is free and takes an email
address. Render only asks for a card at the point you choose a paid instance
type while creating the service - that is the moment the $7 starts, not
before. Billing is monthly and you can delete the service to stop it.

Neither charge is avoidable, and it is worth knowing why before you spend it.

Your whole account - resume, jobs, prepared questions and answers, career
stories, interview history - lives in a single SQLite file. A hosted app needs
somewhere permanent to keep that file, which hosts call a *disk* or *volume*.
Free tiers do not have one: the filesystem is erased every time the app
restarts or redeploys, which happens often. Render's own documentation is
explicit that disks require a paid service. On a free tier you would not be
saving money, you would be starting over on a schedule - which is the exact
thing you are trying to avoid.

Railway (from $5/month) and Fly.io are comparable if you would rather not use
Render. The Dockerfile works on any of them; only `render.yaml` is
Render-specific.

## Why not Vercel

Vercel is the usual home for a Next.js app, and it will not work here, for two
reasons that are both about this app specifically:

1. There is no persistent filesystem, so the SQLite database cannot live
   there.
2. Resume analysis takes about two minutes and report generation about forty
   seconds. They run as background jobs inside the server process. Vercel
   kills functions long before that.

Moving to Vercel would mean swapping SQLite for a hosted Postgres and
rebuilding the background jobs on a queue. That is real work, and nothing you
need unless several people start using this at once.

## Deploying to Render

The code is already on GitHub at `github.com/lisaw1498-pixel/ai-copolite-acct`,
public, with `render.yaml` and the `Dockerfile` in place. Nothing further needs
pushing.

Start here - this link opens Render with the repository already filled in:

**<https://render.com/deploy?repo=https://github.com/lisaw1498-pixel/ai-copolite-acct>**

1. **Sign in or create a Render account.** Free, email address only.

2. **Render reads `render.yaml` and shows you the plan** - one web service,
   a Docker build, a 1 GB disk mounted at `/data`. You do not have to
   configure any of it by hand.

3. **Confirm the Starter instance.** This is where Render asks for a card and
   where the $7.25/month begins.

4. **Paste your Anthropic API key** into `ANTHROPIC_API_KEY` when prompted.
   Use the same key as in your local `.env.local`. It is deliberately not
   stored in this repository: the repo is public, and a key committed to git
   gets found by scrapers and spent by strangers, usually within hours.

   `AUTH_SECRET` is generated by Render for you. `DATABASE_PATH` is already
   set to `/data/app.db` by the blueprint.

5. **Wait for the first build,** roughly five to ten minutes. Render then
   gives you a URL like `https://ai-interview-copilot.onrender.com`. That is
   the web address, and it works from any device.

6. **Create your account on the new site.** The hosted app starts with an
   empty database, so sign up there as you did locally.

### If the first build fails on memory

The Starter instance is 512 MB. That is enough to *run* this app, but
compiling it is heavier than running it, and a Docker build can exhaust a
small instance. If the first deploy fails with an out-of-memory or killed
build, raise the instance one tier in the Render dashboard, let it build, then
drop it back to Starter. You are billed by the hour, so a brief bump costs
cents.

## Your existing data does not come across

This is the part worth thinking about before you deploy.

The hosted app starts empty. Your resume, your four jobs, your sixteen Carrum
questions and answers - all of that is in `data/app.db` on this laptop and
stays there. Deploying does not copy it, and the `.dockerignore` deliberately
keeps the local database out of the image, because a copy baked into the
image would be frozen at build time and overwrite itself on every deploy.

Two options:

- **Start fresh on the hosted version** and re-upload your resume. Simplest,
  and the analysis re-runs in about two minutes.
- **Copy the file up.** Render's paid plans include shell access, so
  `data/app.db` can be uploaded to `/data/app.db` once the service is running
  and then restarted. Ask me and I will walk through it.

Whichever you choose, the two copies do not stay in sync afterwards. Work done
on the hosted version is not on this laptop, and vice versa. Pick one to be
the real one.

## One thing to know about a public URL

Anyone with the link reaches the login page. The account is password
protected, so your data is not exposed, but choose a real password rather than
the test one used locally, because the site is now reachable by anyone.
